# Situs
PCVRワークスペースUI。球面ディスプレイとマウス統一入力により、既存VRワークスペースアプリのUX問題を解決する。

---

## 設計思想

**「首を動かさずに済む」ことを快適さの基準とした、シングルタスク集中型ワークスペース。**

物理ディスプレイが心地よいのは、首を動かさず、指もキーボードから最小限しか離さずに作業が完結するからだ。VRの広大な360°空間に作業を散らすのは、自由度に見えて実は身体的負担を増やしている。

加えて、現在のVRヘッドセットは解像度が低く、複数ウィンドウを同時に実用的な精度で読むことができない。

Situsはこの2つの制約を受け入れ、以下の思想で設計する：

```
アクティブウィンドウ  → 1枚のみ。VR空間内の固定位置で全力表示
HUDピン              → 1枚のみ。アクティブの上に追従するヘッドアップ的参照
フロートピン         → 複数可。空間に固定して「あの位置にあるもの」として参照
バックグラウンド     → サムネイル。存在は示すが読む対象ではない
タスク切り替え       → Tasker（Alt+Tab中心）
```

モバイルOSが「1アプリ前面、バックグラウンドは縮小」という思想で設計されているのと同じ発想を、VRの解像度・身体負担の両制約に適応させる。

## 問題意識

Quest・Picoシリーズ向けのVRワークスペースアプリは、以下の構造的なUX問題を抱えている。

### 1. ウィンドウではなくディスプレイ単位で存在する
Virtual DesktopなどのアプリはWindowsの仮想モニターを丸ごとVR空間に映す。ウィンドウ1枚1枚が独立した空間オブジェクトになっていない。

### 2. K/Mとコントローラーの持ち替えが発生する
- ウィンドウの移動・リサイズ → コントローラー
- ウィンドウ内の操作 → K/M

この持ち替えが作業の流れを断ち切る。

> Galaxy XR・Vision ProなどハイエンドMRはこの問題を解決済み。Situsが対象とするのはQuest・Picoシリーズ（Android OSベース）のユーザー。

## コンセプト

**球面がデスクトップである。**

```
         ┌─────────────────────────────┐
         │                             │
    ┌────┤  [Browser]   [Terminal]     ├────┐
    │    │                             │    │
    │    │         [User]              │    │
    │    │                             │    │
    └────┤  [Editor]    [Slack]        ├────┘
         │                             │
         └─────────────────────────────┘
              球面内側 = 表示面全体
```

- ユーザーは球の中心に位置する
- 球面の内側がディスプレイ面
- Windowsのウィンドウは、球面上に **位置だけ** が貼り付けられる。ウィンドウ自体はフラットなパネルで常に視点を向く（ビルボード表示）。曲面ウィンドウもオプションで選択可能
- カーソルは球面上に**常時存在**する（ウィンドウの有無に関わらず）

## 入力モデル

### マウスで全てを操作する

```
カーソルがウィンドウ上   → そのアプリへ入力を注入（通常のマウス操作）
カーソルがウィンドウ外   → ワークスペース操作モード（移動・リサイズ等）
```

コントローラー不要。持ち替え不要。モード切替不要。

Windowsデスクトップと同じ概念を球面に展開しただけ。

### 球面カーソルの仕組み

```
物理マウスの移動 (delta X, delta Y)
    ↓ RawInput API で差分のみ取得
仮想カーソル位置 (yaw, pitch) を更新
    ↓ レイキャスト
ヒットしたウィンドウのUV座標に変換
    ↓ SendInput
対象ウィンドウへマウスイベントを注入
```

物理カーソルは非表示・中央固定（`ClipCursor` + `ShowCursor(FALSE)`）。

### 物理ディスプレイへの脱出

カーソルが「物理ディスプレイウィンドウ」（後述）の上に来たときだけ **物理カーソルを解放** し、Windowsデスクトップを直接操作させる。物理ディスプレイウィンドウの端に到達したら再度キャプチャを再開する。

UAC・セキュアデスクトップ・予期せぬモーダルなど、Situsの仮想カーソル＋SendInputでは扱いきれないケースのレスキュー経路として機能する。

### ワークスペース操作（マウスのみ）

| 操作 | ジェスチャー |
|---|---|
| ウィンドウ移動 | タイトルバードラッグ（球面上を滑る。アクティブウィンドウは固定位置のため移動不可） |
| フォーカス | クリック |
| Alt+Tab | フォーカス対象がアクティブの固定位置に呼び出される |

### ウィンドウ操作UI（ホバーで出現）

操作UIはアクティブウィンドウ・HUDピン・フロートピンに表示する。

**バックグラウンドウィンドウはサムネイル扱い。**
操作UIは出ない。クリックするとアクティブウィンドウになる。

**上端エリア進入**

カーソルがウィンドウ上端の領域に入るとコントロールバーがウィンドウ上部にフローティング表示される。

```
[ 📌 ][ 🔭 ][ ─────── ドラッグバー ─────── ][ ✕ ]   ← 進入で出現
┌─────────────────────────────────────────────┐
│                                             │
│              ウィンドウ内容                  │
│                                             │
└─────────────────────────────────────────────┘
```

| ボタン | アクティブ時 | ピン留め時 |
|---|---|---|
| 📌 | フロートピン化 | ピン解除 |
| 🔭 | HUDピン化 | ピン解除 |
| ドラッグバー | 球面上を移動 | 同左 |
| ✕ | ウィンドウを閉じる | 同左 |

**下・左・右端ホバー**

```
┌─────────────────────────┐
│                         │
│      ウィンドウ内容      │
│                         │
├──╢                 ╟───┤  ← 左右端にリサイズハンドル
└──────────╧──────────────┘  ← 下端にリサイズハンドル
```

- ホバーでリサイズハンドルが出現
- ドラッグでVRパネルのサイズを変更
- **Windowsのウィンドウサイズへも同期を試みる** が、これは"お願い"ベース。`SetWindowPos` を呼んでもアプリ側が拒否したり最小サイズ制約があったりするため、追従しないケースもそのまま受け入れる

## UI オン/オフ切り替え

ワークスペースUIを丸ごと表示・非表示にするトリガー。VRゲームへの切り替えや、没入体験中に邪魔にならないようにするために必要。

**いずれの状況でも切り替えられるよう、複数の手段を等しく提供する。** 優先順位は設けず、どれかが効かない状況でも他で代替できることを設計目標とする。

| トリガー | 想定状況 |
|---|---|
| キーボードショートカット（例: `Win+Shift+V`） | K/M操作中 |
| 手首のUIアクセスボタン（仮想ボタン） | キーボードから手が離れているとき |
| 視野内ダブルクラップ | 立ち作業中・両手が空いているとき |
| HMDシステムボタン長押し | 上記が使えないとき |
| SteamVRダッシュボード経由 | 任意 |

各トリガーの仕様詳細は実装時に詰める。

#### 視野内ダブルクラップの検出条件

```
- 両手のパームが視野内に存在する
- 手と手の距離が急速に縮まる → 広がる を 2回繰り返す
- 一定時間内（例: 1.5秒以内）に2回完了
```

意図しない動作での誤発動を防ぐため「視野内」の制約を入れる。

## 自動レイアウト

### 基本原則

最小化という概念はない。ウィンドウは常に球面上に存在する。

ただし、バックグラウンドウィンドウの同時描画数は設定で上限を設けられる。上限を超えた分は使用頻度が低いものからTaskerアイコンのみに縮退し、球面上には描画されない（存在はTaskerで示す）。

| 設定 | 内容 | デフォルト |
|---|---|---|
| 最大バックグラウンド描画数 | 球面上に同時表示するバックグラウンドウィンドウの上限 | 8 |

### アクティブウィンドウの位置

アクティブウィンドウは **VR空間内の固定座標（Y+1, 正面）** に常駐する。Alt+Tabでアクティブが切り替わっても、ウィンドウが動くのではなく、その位置に表示される「中身」が入れ替わる。

ユーザーがアクティブの位置をドラッグで変更することはできない（HUDピンとの整合性、および身体負担最小化のため）。位置がずれたと感じたときは **Metaボタン長押しでリセンター** し、目の前に持ってくる。

### 使用頻度による動的配置（バックグラウンド）

```
HUDピン           → アクティブの直上に固定（独立サイズ）
アクティブ        → VR空間の固定位置 (Y+1)、最大サイズ
フロートピン      → ユーザーが置いた位置に固定。サイズ・位置を維持
最近使用          → 中央付近、通常サイズ
バックグラウンド   → 端へ移動、縮小
長期未使用        → さらに端、さらに縮小
```

使用頻度が下がるにつれて、連続的に縮小・外周移動する。急な切り替えではなくグラデーション的に変化。

### ピン留めの2種類

ピン留めには性格の異なる2種類がある。

#### HUDピン（同時に1枚のみ）

アクティブウィンドウの直上に常に追従する、ヘッドアップディスプレイ的なピン。アクティブを切り替えてもHUDはその上に居続ける。

**用途:** コンパイラ出力、チャット、参照中のドキュメントなど「いま見ている作業の上に常時表示しておきたい」もの。

**仕様:**
- 同時に1枚のみ
- アクティブの直上に固定（アクティブ自体がVR空間で固定位置のため、HUDも結果として固定位置）
- HUDのサイズはアクティブのサイズに依存せず **独立**
- HUDをクリックしてもアクティブは切り替わらない（HUDは"見るだけ"のレイヤーとして扱う）

#### フロートピン（複数可）

球面上の任意の位置にユーザーが固定するピン。

**用途:** 動画参照、サンプルコード、サブの参照ウィンドウなど「あの位置に置いておけば必ずある」もの。

**仕様:**
- 同時に複数可
- 使用頻度ロジックの対象外（サイズ・位置を維持）
- ユーザーが置いた位置に留まり、アクティブが変わっても動かない
- 空間記憶を活用する設計

```
         [ HUDピン ]      ← アクティブの直上（固定）
━━━━━━━━━━━━━━━━━━━━━━━━
       [ アクティブ ]      ← VR空間の固定位置 (Y+1)
━━━━━━━━━━━━━━━━━━━━━━━━
  [縮] [縮小中] [フロート] [縮]   ← バックグラウンド + フロートピン
```

## 球面の追従挙動

球面デスクトップは **ヘッドの回転には追従しない。位置（並進）にのみ追従する。**

```
ユーザーが歩く・身体ごと向きを変える
  → 球面の中心がユーザーに付いてくる

ユーザーが首を回す
  → 球面は世界に対して静止。視線の先には別のウィンドウが見える

球面の向きを再設定したいとき
  → Metaボタン長押しでリセンター
  → アクティブが目の前に戻る
```

UIが顔に貼り付いている感覚（VR酔いの原因）を完全に避けつつ、首を動かす範囲はユーザー自身が決める。

---

## 球面の範囲

デフォルト正面180°。設定で変更可能。

```
デフォルト (180°):        設定変更例:
    [前半球のみ]              [270°] [360°]
  ←  90° | 90°  →         広いほど首の回転が増える
```

設計思想（首を動かさない）からすると180°でも広めだが、ユーザーごとの作業スタイルに合わせて調整できるようにする。

## 物理ディスプレイウィンドウ

物理モニター自体を「Situs上の1ウィンドウ」として表示できる。

```
Tasker: [🌐] [⌨️] [📁] [🖥️ Display 1] [🖥️ Display 2]
                              ↑ 物理ディスプレイもアイコンとして並ぶ
```

- **ディスプレイの数だけ「ディスプレイウィンドウ」が用意される**（3画面なら3アイコン、3ウィンドウ）
- 通常のウィンドウと同じく球面上に配置・リサイズ可能
- カーソルがディスプレイウィンドウ上に乗ると **物理カーソルが解放され、Windowsを直接操作できる**（前述）

**位置づけ:** これは常用するためのものではなく、**レスキュー用** の機能。
- UAC等の特殊なフォーカス処理が必要なケース
- Situsが管理していないモーダルダイアログへの対処
- 普段は表示しない or 端に小さく配置しておく想定

通知についても、Action Centerやアプリごとのトーストは **Situs側の通知システム** で吸い上げて表示する（詳細は別途設計）。

## Tasker

タスクバーとタスクスイッチャーを統合した単一のUI。別個のオーバーレイは存在しない。

```
         ┌─────────────────────────────┐
         │                             │
    ┌────┤  [Browser]   [Terminal]     ├────┐
    │    │                             │    │
    │    │         [User]              │    │
    │    │                             │    │
    └────┤  [Editor]    [Slack]        ├────┘
         │  ━━━━━━━━━━━━━━━━━━━━━━━━  │
         │  [🌐][ ⌨️ ][📁][🖥️]   🕐 12:34│
         │    ↑フォーカス（拡大アニメ）  │
         └─────────────────────────────┘
              球面底部に弧状で固定
```

### レイアウト（2段構成）

**上段：アプリアイコン行**

```
│ [フロートピン][フロートピン] │ [アクティブ][アプリ][アプリ]… │ [HUDピン] │
  ←─ フロートピン ─→           ←──── 通常アプリ ────→         ←HUD→
```

| エリア | 内容 |
|---|---|
| 左（セパレート） | フロートピンアプリ |
| 中央 | 通常実行中アプリ。**一番左がアクティブアプリ** |
| 右（セパレート） | HUDピンアプリ |

アクティブアプリのアイコンは**座布団（アイコン背景）の色**で他と区別する。アクティブが切り替わると中央の並び順が更新され、アクティブが一番左に来る。

**下段：システム行**

```
[ ⊞ ][ 🖥 ][ 🖥 ] │ [      メディアプレーヤー / 通知エリア      ] │ [🔔][⚙️][ 09:12 ]
```

| ボタン | 機能 |
|---|---|
| スタートメニュー（⊞） | Windows スタートメニューを開く（`SendInput` で Win キー送信） |
| ディスプレイ表示（🖥） | 物理モニターをウィンドウパネルとして表示（モニター数分） |

### メディアプレーヤー／通知エリア

下段中央に常駐するエリア。通常時はメディアプレーヤーを表示し、通知が来た場合は一時的に通知内容に切り替わる。

```
通常時:  [ アルバムアート | 曲名 / アーティスト | ◀◀  ▶  ▶▶ ]
通知時:  [ アプリアイコン | 通知タイトル / 本文              ]  ← 数秒後にメディアに戻る
```

### 通常状態
- 実行中ウィンドウ＋物理ディスプレイのアイコン一覧を常時表示
- クリックでそのウィンドウをアクティブ化
- 時計・システムトレイ相当の情報

### 新規ウィンドウ起動時
```
Taskerのアイコンがバウンスアニメーション（Mac Dock式）
  → ウィンドウは球面上の自動レイアウト位置に静かに配置
  → アクティブウィンドウは変わらない
  → ユーザーが任意のタイミングで切り替える
```

通知は最小限。作業の流れを断ち切らない。

### Alt+Tab 操作時
```
Alt 押下
  → Taskerがアクティブ状態に遷移（強調表示）

Tab を押すたびに
  → Tasker上のフォーカスアイコンが拡大アニメーション
  → アクティブインジケーター（アイコン下のドット等）が移動
  → 球面上のウィンドウは動かない（全ウィンドウが既に見えているため不要）
  → サムネイルプレビューも不要

Alt 離す
  → フォーカス中のウィンドウがアクティブの位置（VR空間固定座標）に呼び出される
  → Taskerは通常状態に戻る
```

WindowsのタスクスイッチャーはAlt+Tab時に「一時的なオーバーレイ」として別に出現するが、Situsでは**Tasker自体がスイッチャーとして動的に動く**。UI要素の数を増やさずに同じ操作を実現する。

## 機能

- **ウィンドウ単位のVR表示** — モニター丸ごとではなく、1ウィンドウ = 1パネル
- **物理ディスプレイのウィンドウ化** — レスキュー用に物理モニターも1パネルとして配置可能（マルチモニター対応）
- **球面ワークスペース** — 全ウィンドウが球面上に配置される（パネル自体は視点を向くビルボード）
- **Tasker** — 球面底部に固定。タスクバー＋タスクスイッチャー＋メディアプレーヤー＋通知を統合
- **マウス統一入力** — ワークスペース操作を含む全操作をマウスで完結
- **物理カーソル脱出** — ディスプレイウィンドウ上では物理カーソルを解放しレスキュー経路を確保
- **Alt+Tab連携** — フォーカス対象がアクティブの固定位置に呼び出される
- **自動レイアウト** — 使用頻度に応じた連続的な縮小・移動
- **HUDピン／フロートピン** — 用途の異なる2種類のピン留め
- **UIオン/オフ切り替え** — 複数の手段で確実にトグル
- **位置のみ追従する球面** — ヘッド回転には追従せず、リセンターで再設定
- **ハンドトラッキング対応** — VRアプリ操作にコントローラー不要
- **VRアプリとの共存** — OpenVR Overlay APIによりVRゲーム上にオーバーレイ表示（XSOverlay同方式）
