# Situs

PCVRワークスペースUI。球面ディスプレイとマウス統一入力により、既存VRワークスペースアプリのUX問題を解決する。

---

## 設計思想

**VRの解像度制約を前提にした、シングルタスク集中型ワークスペース。**

現在のVRヘッドセットは解像度が低く、複数ウィンドウを同時に実用的な精度で読むことができない。この制約を無視して「マルチウィンドウを全部同時に使える」ように設計しても体験は改善しない。

Situsはこの制約を受け入れ、以下の思想で設計する：

```
アクティブウィンドウ  → 1枚のみ。正面中央で全力表示
ピン留めウィンドウ   → 1枚のみ。参照用に常時視野内
バックグラウンド     → サムネイル。存在は示すが読む対象ではない
タスク切り替え       → タスクバー統合スイッチャーで素早く
```

モバイルOSが「1アプリ前面、バックグラウンドは縮小」という思想で設計されているのと同じ発想をVRワークスペースに適用する。

---

## 問題意識

Quest・Picoシリーズ向けのVRワークスペースアプリは、以下の構造的なUX問題を抱えている。

### 1. ウィンドウではなくディスプレイ単位で存在する
Virtual DesktopなどのアプリはWindowsの仮想モニターを丸ごとVR空間に映す。ウィンドウ1枚1枚が独立した空間オブジェクトになっていない。

### 2. K/Mとコントローラーの持ち替えが発生する
- ウィンドウの移動・リサイズ → コントローラー
- ウィンドウ内の操作 → K/M

この持ち替えが作業の流れを断ち切る。

> Galaxy XR・Vision ProなどハイエンドMRはこの問題を解決済み。Situsが対象とするのはQuest・Picoシリーズ（Android OSベース）のユーザー。

## コンセプト

**球面がデスクトップである。**

```
         ┌─────────────────────────────┐
         │                             │
    ┌────┤  [Browser]   [Terminal]     ├────┐
    │    │                             │    │
    │    │         [User]              │    │
    │    │                             │    │
    └────┤  [Editor]    [Slack]        ├────┘
         │                             │
         └─────────────────────────────┘
              球面内側 = 表示面全体
```

- ユーザーは球の中心に位置する
- 球面の内側がディスプレイ面
- Windowsのウィンドウは球面上に個別に貼り付けられる
- カーソルは球面上に**常時存在**する（ウィンドウの有無に関わらず）

---

## 入力モデル

### マウスで全てを操作する

```
カーソルがウィンドウ上   → そのアプリへ入力を注入（通常のマウス操作）
カーソルがウィンドウ外   → ワークスペース操作モード（移動・リサイズ等）
```

コントローラー不要。持ち替え不要。モード切替不要。

Windowsデスクトップと同じ概念を球面に展開しただけ。

### 球面カーソルの仕組み

```
物理マウスの移動 (delta X, delta Y)
    ↓ RawInput API で差分のみ取得
仮想カーソル位置 (yaw, pitch) を更新
    ↓ レイキャスト
ヒットしたウィンドウのUV座標に変換
    ↓ SendInput
対象ウィンドウへマウスイベントを注入
```

物理カーソルは非表示・中央固定（`ClipCursor` + `ShowCursor(FALSE)`）。

### ワークスペース操作（マウスのみ）

| 操作 | ジェスチャー |
|---|---|
| ウィンドウ移動 | タイトルバードラッグ（球面上を滑る） |
| フォーカス | クリック |
| Alt+Tab | アクティブウィンドウが正面 (yaw=0, pitch=0) へ移動 |

### ウィンドウ操作UI（ホバーで出現）

操作UIはアクティブウィンドウとピン留めウィンドウのみに表示する。

**バックグラウンドウィンドウはサムネイル扱い。**
操作UIは出ない。クリックするとアクティブウィンドウになる。

**上端ホバー（アクティブ／ピン留めウィンドウのみ）**

```
┌─────────────────────────┐
│  [ピン留め]  [閉じる]    │  ← フローティングボタン（上端ホバーで出現）
├─────────────────────────┤
│                         │
│      ウィンドウ内容      │
│                         │
└─────────────────────────┘
```

- アクティブウィンドウ → ピン留めボタン ＋ 閉じるボタン
- ピン留めウィンドウ → ピン留め解除ボタン ＋ 閉じるボタン

**下・左・右端ホバー**

```
┌─────────────────────────┐
│                         │
│      ウィンドウ内容      │
│                         │
├──╢                 ╟───┤  ← 左右端にリサイズハンドル
└──────────╧──────────────┘  ← 下端にリサイズハンドル
```

- ホバーでリサイズハンドルが出現
- ドラッグでVRパネルのサイズを変更
- **Windowsのウィンドウサイズと同期**（`SetWindowPos` でWindows側も追従）

## UI オン/オフ切り替え

ワークスペースUIを丸ごと表示・非表示にするトリガー。VRゲームへの切り替えや、没入体験中に邪魔にならないようにするために必要。

### メイントリガー（推奨）

**視野内ダブルクラップ**
両手を視点正面で2回叩く（拍手×2）。

```
検出条件:
  - 両手のパームが視野内に存在する
  - 手と手の距離が急速に縮まる → 広がる を 2回繰り返す
  - 一定時間内（例: 1.5秒以内）に2回完了
```

意図しない動作での誤発動を防ぐため「視野内」の制約が重要。

### その他のトリガー（参考・併用候補）

| トリガー | 状況 | 備考 |
|---|---|---|
| キーボードショートカット（例: `Win+Shift+V`） | K/M操作中 | 最も確実。ゲーム中は使いにくい |
| 手首ウォッチタップ（XSOverlay方式） | 常時 | 片方の手首に仮想ボタンを表示、もう一方の手でタップ |
| HMDシステムボタン長押し | ゲーム中 | HMD機種依存（Quest・Picoで異なる） |
| SteamVRダッシュボード経由 | 任意 | 既存UIで確実だが手間 |
| 手首を2回素早く返す（ウリストフリック） | 片手で完結 | ダブルクラップより誤認識しやすい |
| 特定のハンドポーズ保持（例: 両手でタイムアウトサイン） | 任意 | 直感的だが覚えにくい |

## 自動レイアウト

### 基本原則

全ウィンドウを常時描画する。最小化という概念はない。

### 使用頻度による動的配置

```
アクティブ        → 正面中央 (yaw=0, pitch=0)、最大サイズ
最近使用          → 中央付近、通常サイズ
バックグラウンド   → 端へ移動、縮小
長期未使用        → さらに端、さらに縮小
```

使用頻度が下がるにつれて、連続的に縮小・外周移動する。急な切り替えではなくグラデーション的に変化。

### ピン留め（固定ウィンドウ）

バックグラウンドに回っても縮小・移動させたくないウィンドウに使う。
動画参照、サンプルコード表示など「見ながら作業する」用途を想定。

**仕様:**
- 最大1枚まで同時にピン留め可能
- ピン留めウィンドウは使用頻度ロジックの対象外（サイズ・位置を維持）
- **アクティブウィンドウが変わっても、常にアクティブウィンドウの上に追従する**

```
         [ ピン留め ]      ← アクティブウィンドウの上
━━━━━━━━━━━━━━━━━━━━━━━━
       [ アクティブ ]      ← 正面中央
━━━━━━━━━━━━━━━━━━━━━━━━
  [縮] [縮小中]  [縮小中] [縮]   ← バックグラウンド（使用頻度で位置・サイズが変動）
```

## 球面の配置

球面デスクトップの位置はヘッドに追従する。回転は追従しない。

```
位置（XYZ）: ヘッドに追従 → 物理的に移動しても常に同じ距離に球面がある
回転（Yaw/Pitch）: ワールド固定 → 首を回しても球面は回転しない
```

- 顔の向きを変えると球面の別の領域が見える（ワールド固定の回転）
- 体ごと移動しても球面は常に自分を中心に存在する（位置追従）

**リセンター機能**：任意のタイミングで現在の向きを正面として球面を再配置できる。

---

## 球面の範囲

デフォルト正面180°。設定で変更可能。

```
デフォルト (180°):        設定変更例:
    [前半球のみ]              [270°] [360°]
  ←  90° | 90°  →         広いほど首の回転が増える
```

## タスクバー／タスクスイッチャー

タスクバーとタスクスイッチャーは統合された単一のUI。別個のオーバーレイは存在しない。

```
         ┌─────────────────────────────┐
         │                             │
    ┌────┤  [Browser]   [Terminal]     ├────┐
    │    │                             │    │
    │    │         [User]              │    │
    │    │                             │    │
    └────┤  [Editor]    [Slack]        ├────┘
         │  ━━━━━━━━━━━━━━━━━━━━━━━━  │
         │  [🌐][ ⌨️ ][📁]   🕐 12:34  │
         │    ↑フォーカス（拡大アニメ）  │
         └─────────────────────────────┘
              球面底部に弧状で固定
```

### レイアウト

```
[ ⊞ ][ 🖥 ] │ [アイコン][アイコン][アイコン]… │ 🕐 12:34
  ↑    ↑
スタート デスクトップ表示
```

左端に固定ボタン2つ、中央にウィンドウアイコン一覧、右端に時計。

| ボタン | 機能 |
|---|---|
| スタートメニュー（⊞） | Windows スタートメニューを開く（`SendInput` で Win キー送信） |
| デスクトップ表示（🖥） | Windows デスクトップをウィンドウパネルとして表示（`Win+D` 相当） |

### 通常状態
- 実行中ウィンドウのアイコン一覧を常時表示
- クリックでそのウィンドウを正面 (yaw=0, pitch=0) に呼び出す
- 時計・システムトレイ相当の情報

### 新規ウィンドウ起動時
```
タスクバーのアイコンがバウンスアニメーション（Mac Dock式）
  → ウィンドウは球面上の自動レイアウト位置に静かに配置
  → アクティブウィンドウは変わらない
  → ユーザーが任意のタイミングで切り替える
```

通知は最小限。作業の流れを断ち切らない。

### Alt+Tab 操作時
```
Alt 押下
  → タスクバーがアクティブ状態に遷移（強調表示）

Tab を押すたびに
  → タスクバー上のフォーカスアイコンが拡大アニメーション
  → アクティブインジケーター（アイコン下のドット等）が移動
  → 球面上のウィンドウは動かない（全ウィンドウが既に見えているため不要）
  → サムネイルプレビューも不要

Alt 離す
  → フォーカス中のウィンドウが正面に移動
  → タスクバーは通常状態に戻る
```

Windowsのタスクスイッチャーは「一時的なオーバーレイ」として別に存在するが、Situsでは**タスクバー自体がスイッチャーとして動的に動く**。UI要素の数を増やさずに同じ操作を実現する。

## 機能

- **ウィンドウ単位のVR表示** — モニター丸ごとではなく、1ウィンドウ = 1パネル
- **球面ワークスペース** — 全ウィンドウが球面内側に配置される
- **タスクバー** — 球面底部に固定。ウィンドウ一覧・時計
- **マウス統一入力** — ワークスペース操作を含む全操作をマウスで完結
- **Alt+Tab連携** — アクティブウィンドウが自動で正面に来る
- **自動レイアウト** — ウィンドウを自動整列
- **UIオン/オフ切り替え** — ダブルクラップで即座にトグル
- **ハンドトラッキング対応** — VRアプリ操作にコントローラー不要
- **VRアプリとの共存** — OpenVR Overlay APIによりVRゲーム上にオーバーレイ表示（XSOverlay同方式）
